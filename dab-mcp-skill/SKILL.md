# DAB SQL 财务、共识、估值与涨跌幅

## 硬性规则

- 将本 MCP 作为公司财务、市场共识、估值及股票或指数 Chg 的默认唯一数据源。MCP 缺失、过时或不可用时直接说明。
- 服务只读；只调用发现、读取和执行工具，不调用创建、更新或删除工具。
- 不用名称相近但定义不同的科目代替用户所需指标，不把实际财报与共识预估混为一谈。
- 所有 Agent 派生值都使用计算器、代码运行时或电子表格确定性计算，不心算、估算或静默补零。

## 适用场景
- 适用于资料定义明确的金融查询。有明确的公司（代码）、科目、日期（期间）、币别（可选）
- 适用于少量公司、科目和期间的财务、共识或价格表现查询。公司数量少于 50、科目少于 50；

## 不适用场景
- 不适用于定义模糊或主观判断的问题，例如“业绩反转”“最值得投资”“Top10 ROE”“行业前20”等
- 没有明确的公司、科目、期间时，请主动告知用户要求提供精确的查询条件。

## 连接与元数据

- 服务：`dab-sql`
- 端点：`http://internal.aitools:5000/mcp`
- 传输：Streamable HTTP

若当前客户端尚未配置服务，按客户端原生方式添加并刷新会话。不要用普通 `GET`、命令行 HTTP 或手写 JSON-RPC 冒充 MCP 验证；普通 `GET` 返回 `406` 不代表服务不可用。

每个任务的第一次 MCP 调用必须是 `describe_entities`：

1. 已知所需实体时，直接调用 `describe_entities(entities=[...])`，不要先调用 `nameOnly=true`。
2. 只有实体名称未知、需要探索能力时，才先用 `describe_entities(nameOnly=true)`，随后读取目标实体详情。
3. 同一任务复用元数据。仅在客户端有可验证的同日缓存，且服务、端点和版本状态未变时跨任务复用；参数错误、字段不符或服务更新后立即刷新。
4. 若 `permissions` 为空，依据说明中的 `access type`：带参数的实体通常用 `execute_entity`，仅有字段的视图用 `read_records`。

记录通常位于 `value.value[]`，但必须按实际响应解析。始终核对返回的代码、日期、财报类型、币别、科目和值，不依赖请求顺序或旧会话结构。

## 批量优先的查询规划

不要把“紧凑查询”理解成“逐公司发大量小请求”。先按预计返回行数规划批次，再在结果异常时缩小范围。

### 预计行数

- `financialPeriod`：约 `公司数 × 期间数`
- `financial`：约 `公司数 × 期间数 × 科目数`
- `estFinancial`：每个 `perDate` 约 `公司数 × items 数`
- 接口可能额外返回边界期或比较期，预留约 25% 余量。

### 默认批次策略

1. 预计不超过 200 行：把多家公司、所需期间和科目合并为一次调用。
2. 预计 201–800 行：拆成预计约 200 行的批次；长历史优先按日期窗口拆，大股票池优先按公司拆。
3. 预计超过 800 行：同时按公司和日期分块，但每块仍应包含多家公司或多个期间。
4. 不同 `PerTypeCode` 分开查询；同一类型、窗口和科目则尽量合并。
5. 默认并发不超过 4 个独立请求。批量优先于并发扇出；不要仅因为可以并发就逐公司查询。
6. `estFinancial` 每次只有一个 `perDate`，因此按日期调用，但同一日期应合并所有目标公司和 items。

例如，6 家公司、8 个季度、3 个科目预计为 `6 × 8 × 3 = 144` 行：默认用一次批量 `financialPeriod` 和一次批量 `financial`，而不是分别调用 24 次。只有响应失败、疑似截断或覆盖不完整时才拆批。

### 完整性检查与重试

每批完成后在执行端解析并检查：

- 以 `code + yymm_unified + PerTypeCode + item/accitem` 建立唯一键并去重。
- 检查公司覆盖、目标期间覆盖、科目覆盖、币别和单位；缺失值不得当作 `0`。
- 接口可能返回窗口外的相邻期间，按实际 `yymm_unified` 和目标集合过滤。
- 仅对缺失的公司、期间或科目子集补查，不重复整个成功批次。
- 超时、无法解析、疑似截断或返回量明显异常时，将当前批次二分后重试；参数或字段错误则先刷新实体元数据。
- 异常数值先检查原始记录、期间、单位和币别。仅当异常会实质影响答案且可能是请求或解析问题时，做一次单公司定向复查；若结果相同，原样披露并标记异常，不反复查询。

工具返回后优先在执行端只保留任务需要的行列，不把完整 JSON 或完整科目目录交给模型或输出给用户。

## 股票代码

| 市场 | 格式 | 示例 |
|---|---|---|
| CN | 6 位数字 | `000001`、`600000` |
| HK | 5 位数字 | `00700`、`09988` |
| TW | 4 位数字 | `1101`、`2330` |
| JP | 4 位数字 + JP | `6981 JP` |
| KR | 6 位数字 + KS | `005930 KS` |
| US | 英文代码 + US | `AAPL US`、`NVDA US` |
| 其他 | Ticker + 市场 | `BAF IN`、`DBS SP`、`BMW GR` |

始终把代码当字符串，保留前导零、空格和市场后缀。返回的 `mkt` 可能与输入后缀不同，例如 `005930 KS` 可返回 `mkt=KR`；不得据此重拼代码。用户只给公司名称且存在多重上市或证券类型歧义时，先确认标的；服务没有通用名称转代码实体时，不擅自用外部来源解析。

## 已公布财报

1. 明确公司、期间、日历季度或财政季度、财报类型、科目和币别；只有会改变结果的歧义才询问用户。
2. 需要标准财报科目时，以 `read_records(entity="accitemList", first=500)` 读取并分页。任务内复用目录；有可验证的同日缓存时不重复读取。按业务定义选科目，不把旧代码当永久常量。
3. 对同一 `PerTypeCode`，先将目标公司合并调用 `financialPeriod`。用户已明确季度、年度或半年报时分别固定为 `2`、`1`、`3`；只有报表粒度未知时才使用 `0` 自动选择。从返回值确定每家公司的 `yymm_unified`、`yymm_dt`、`InterimNo` 和币别。
4. 再按批次策略调用 `financial`，`acc_items` 只包含所需科目；返回后按代码、标准化期间和科目过滤。
5. 查询“最新一期”时，按公司分别取最大的 `yymm_unified`，不要依赖返回顺序。使用覆盖各公司原始 `yymm_dt` 的共同窗口；只有缺失公司才扩大或单独补查。

查询“最近 N 个季度”时，初始窗口覆盖约 `N + 2` 个季度以容纳非自然财年及边界期；不要无理由回溯更长历史。单公司取其最新 N 个标准化季度；多公司横向比较默认取最新 N 个共同 `yymm_unified`，共同期间不足时披露差异并按用户目的决定是否改为各自最新 N 季。

`from/to` 可能按原始财报日 `yymm_dt` 过滤。美国、日本等非自然财年公司即使 `yymm_unified` 对齐，原始期末也可能落在上一季、当年 9 月或次年 3 月。

跨市场“2025Q1”默认按 `yymm_unified=2025-03-31` 对齐，不能统一筛成 `InterimNo=1`；只有用户明确要求财政 Q1 时才按 `InterimNo=1`。`to_ccy=ALL` 表示保留原始财报币别，不能直接加总不同币别金额。

## 市场共识预估

- 尚未公布期间、一致预期或估值使用 `estFinancial`；已公布数据使用 `financial`。
- 固定 items：`BPS`、`EPS`、`DPS`、`NET`、`SAL`、`CPX`、`PE`、`PB`、`GRM`、`OPREBI`。`NET` 为归母净利润，`SAL` 为营收，`GRM` 为毛利率百分比，`OPREBI` 为营业利润金额；其余以返回的 `desp` 为准。
- `val` 是市场共识均值。明确标为“市场共识预估”，不能表述为公司指引或已公布数据。
- 使用 `perDateType=CAL` 和 `yymm_unified` 做跨市场对齐，同时保留 `yymm_dt` 说明实际财政期末。
- 每个目标 `perDate` 调用一次，并在该调用中合并目标公司和 items。仅在完整性检查失败时补查缺失子集。
- 比较实际值与预估值前，核对期间、类型、定义、单位和 `ccy/to_ccy`。预估币别不得从实际财报推定。

## 涨跌幅

1. 调用 `dateList` 并检查 `UpdateDate`，取得 DOD、WOW、MTD、YTD、一年期等实际起止日期；字段可能为 `1Y` 或 `1YY`，以当次返回为准，不自行拼接日期。
2. 查询指数前调用 `indexList`，使用服务返回的内部指数代码。
3. 将实际区间传给 `priceChg`；普通区间使用 `ptype=Chg`。股票使用复权价，指数未指定 `is_adj` 时使用默认值 `1`。
4. 相同区间、类型和币别的多只股票或指数优先批量查询。需要相对表现时，按 `股票 Chg - 基准 Chg` 确定性计算，并说明基准选择。

## 计算与研究判断

- 优先采用 MCP 已直接返回且定义匹配的指标。派生计算使用原始完整精度，只在最终展示时四舍五入，并说明公式、口径、样本、币别和舍入位数。
- 单一公司年度成长可按 `(下一年度共识 / 上一年度实际 - 1) × 100%` 计算。分母为负值或接近零时，改为说明转盈、转亏或低基期，不给误导性普通成长率。
- 多股票整体营收 YoY 使用同一可比样本：`(Σ本期营收 / Σ上期营收 - 1) × 100%`，不能简单平均公司 YoY。
- 不直接加总不同币别金额。只有本期与上期均按明确且一致的汇率口径转换到同一 `to_ccy` 后，才能计算同币别合计。
- MCP 未提供所需估值倍数、完整价格或事件时间资料时，不判断贵贱、波动或因果，不把涨跌归因于财报。

## 输出

- 清楚列出公司、代码、期间、科目口径、币别、单位及数据性质（实际或市场共识）。
- 分开呈现供应商事实、Agent 派生值和分析判断；缺失、异常、财期差异或币别转换仅在实际发生时说明。
- 多公司比较优先使用横向表格；不同币别金额保留各自币种，不制造不可比的合计。
- 未经用户要求，不把有限指标包装成买入、卖出或目标价建议。
