# MCP 实施计划：能力摘要、按需详情与部分失败结果

状态：摘要目录、按需详情、部分失败统计已实现；本项目开发 MCP 的协议及只读联调结果见文末实施记录。数据库迁移脚本仅交付管理员手工执行。

## 1. 目标与范围

CB／ECB 实战暴露两类问题：

1. 行情与库存说明包含必要的参数组合、日期、比例尺度和关联限制，不能简单删短；能力增加后，每个任务读全部正文会带入大量无关内容。
2. execute_sql 多结果集读取中途失败时，已有结果可能被保留，但大小仍为零；当前结果集尚未交付的行也可能计入 returnedRows。

先实施能力摘要与详情分离，再独立修复部分失败统计。两项分别验收，不夹带缓存、引用搜索重构、数据库定序调整或其他业务功能。

本计划对能力读取的新约定优先于 capabilities-plan.md 中旧的“首次完整读取全部 desp”约定。实施时同步正式文档，不长期保留相互矛盾的描述。

## 2. 不变的设计边界

- Agent 只面对业务工具、公开字段和简洁结果；不公开认证模式、配置函数名、底表、内部备注及日志诊断。
- SKILL 与 grant 对 Agent 都是能力条目，不暴露 itype，不按后台类型决定是否加载正文。
- 不增加 always_load，也不以 summary 是否填写作为加载开关。
- 每次调用独立执行，不保存“已读详情”或“已授权”会话状态，不缓存授权。
- procedure 对所有账号继续强制核验当前身份的 iname 授权、真实用户 procedure、系统同名冲突和 EXECUTE 权限。读过摘要或详情不构成授权。
- 未配置有效 capabilities.listFunction 时，目录、详情及 execute_procedure 均不注册，只保留四项通用工具；相关提示词不得提及未开放工具。
- 现有 AD 前置 check 的适用条件和失败关闭规则不变。SQL 密码模式仍不走 AD 入口检查，但必须经过 procedure 独立目录授权检查。
- 使用相同配置连接身份访问目录函数；不接受 Agent 指定用户名，不直接开放 tools_info 或 base 函数。

## 3. 数据库契约

### 3.1 tools_info

仅作以下结构调整：

| 字段 | 最终约定 |
|---|---|
| summary | 新增 nvarchar(1000) NOT NULL，必须包含非空白文本；建议写清用途、适用条件、必要限制及何时读取详情 |
| desp | 保持 nvarchar(max) NOT NULL；无详情填写空字符串 N''，有详情保存业务口径、步骤和示例 |
| 其他字段 | id、itype、iname varchar(150)、remark、upd_time、active 不变 |

不增加 has_desp 实体列，不增加对象类型列、触发器或时间自动更新机制。摘要由管理员明确填写，不自动截取 desp，不以正文回填缺失摘要。

summary 不增加数据库 CHECK 约束，由管理员维护并由 MCP 校验；最终所有记录（包括暂时 inactive 的记录）均应具有非空白摘要，避免恢复启用时暴露不完整契约。

### 3.2 正文有无判定（按已简化的 SQL 实现）

无详情的维护约定是填写空字符串 `N''`，不是 NULL，也不要仅填写换行、Tab 或其他不可见字符。has_desp 的唯一计算规则为：

```sql
CONVERT(bit, CASE WHEN i.desp <> N'' THEN 1 ELSE 0 END)
```

- 不恢复 Unicode 空白字符表，不添加 REPLACE、TRIM、额外 COLLATE 或数据库 CHECK 约束。
- 比较遵循此 SQL 表达式及该列定序；不能把它解释为 .NET 的 string.IsNullOrWhiteSpace。普通空格、换行和其他字符的判定以 SQL 返回值为准。
- MCP 以非空 bit 类型的 has_desp 为准，不另算一套正文空白规则，也不把仅含换行的正文判成配置错误。
- desp 契约为非 NULL 文本，函数与 MCP 原样返回，包括其中的空格、换行及 Markdown。has_desp=false 时不强制把原值改成空字符串；正常维护值应是 N''。
- 如返回 NULL desp 或 has_desp=true 却返回长度为零的 desp，属于明确契约错误，返回 capabilities_unavailable；不把 NULL 自动转换成空正文。
- summary 是独立的必读摘要，MCP 仍拒绝 NULL、空字符串或纯空白摘要（使用 string.IsNullOrWhiteSpace）。这不是对 desp 有无判定的重新计算。

### 3.3 函数输出

复用已配置的无参数 list_capabilities()，base 继续仅供管理员模拟。公开函数最终返回：

| 字段 | 类型及含义 |
|---|---|
| id | 非空 int；当前身份目录内唯一 |
| ord | 非空 int；同一 tool 按 tools_grant.ord、tools_role_group.ord 成对选取最靠前位置，去重后按两层权重及 id 生成连续展示序号 |
| iname | 文本；skill 为空白，当前身份有效 grant 返回完整三段对象名；兼容 NULL 为空对象授权 |
| summary | 非空白文本 |
| has_desp | 非空 bit，由原始 tools_info.desp 自动计算 |
| desp | 非 NULL 文本，直接返回 i.desp；保留原有 Markdown，不拼接、不裁剪、不格式化 |

summary 与 desp 均原样返回，不再自动添加 ### SKILL 或 ### OBJECT 标题。条目身份由 id、iname 表达；正文可以自行使用 Markdown 标题、列表和 SQL 代码块。has_desp 只按 3.2 的 SQL 表达式计算。摘要不由正文或标题推导。

身份过滤、active、角色分配、去重、ord 规则保持不变；remark、itype 不公开。函数列可以扩展，但 MCP 仅选取约定字段。

checkFunction 继续判断身份是否有有效目录记录，不因某条 has_desp=false 而拒绝。配置缺陷与权限撤销仍分别反馈，任何无法核验的 procedure 调用都不执行。

## 4. MCP 工具契约

### 4.1 list_capabilities(offset=0)

- 保留仅 offset 的调用方式、默认 pageSize=100 及现有配置范围；不增加用户名、关键词或类型过滤。
- SQL 显式读取 id、ord、iname、summary、has_desp，不选择、读取或拼接 desp 到 MCP。数据库仍可能为计算 has_desp 检查正文；本目标是减少正文传输和 Agent 上下文，不承诺数据库完全不读取 desp。
- 按 ord、id 稳定排序，取 pageSize+1 判断后续；ord 用于内部排序，不要求暴露原始数字。
- structuredContent 返回 items（每项 id、iname、summary、has_desp）、has_more、next_offset。无下一页时 next_offset=null。
- content.text 只返回简短页摘要和续页提示，不重复整份条目。
- 对最终响应序列化结果应用现有 maxResultSizeKb 预算；不截断单条摘要。首条放不下时返回 capability_too_large；后续条目放不下时结束本页，next_offset 按实际返回条数计算。
- summary 缺失、空白、字段类型错误、重复 id 或顺序异常，整页失败，不以 desp 回填，不静默跳过条目。
- 保留当前空目录语义：AD 有效首页目录为空时拒绝；SQL 密码模式可返回空目录；越界页正常返回空页。空目录在任何账号模式下都不能授权 procedure。

### 4.2 get_capability_details(id)

新增一个按需详情工具，与 list_capabilities 共用启用条件；不增加配置函数或直接读取底表。

- id 为必填正 int；非法输入在查询前拒绝。
- 每次通过当前身份过滤后的配置目录函数，以参数化 WHERE id=@id 查询。不得复用曾经读到的正文或授权结果。
- 显式读取 id、iname、summary、has_desp、desp，最多探测两条以发现重复；返回 id 必须与请求一致。同 id 若出现多条，按契约错误处理，不取第一条放行。
- 无可见条目返回 access_denied／用户没有访问权限，不区分删除、撤权或其他身份持有该条目。
- structuredContent 返回 id、iname、summary、has_desp、desp；content.text 仅返回详情已读取或该条目无详情的简短说明。
- has_desp=false 时成功返回原始 desp（正常维护值为 ""）及完整 summary；不是权限错误，不编造正文，也不把 summary 复制成 desp。
- has_desp/正文契约按 3.2 校验；禁止使用 string.IsNullOrWhiteSpace(desp) 推翻数据库计算的 has_desp。获取详情时若条目已变为无详情，按本次新结果正常返回，不使用上次列表结果覆盖它。
- 详情流式读取并受 maxResultSizeKb 限制。单条超限返回 capability_too_large，不交付半份正文；本轮不增加正文分页接口。
- 查询故障、权限错误、取消沿用当前安全错误分类；日志保留内部诊断，对外不返回函数或底表细节。

has_desp 来自受信任数据库函数，MCP 校验类型及 3.2 明确列出的错误，不复刻 SQL 字符串比较，不从 Markdown 内容判断是否授权。

### 4.3 注册与返回兼容性

- 未启用目录：四项工具。
- 启用目录：四项通用工具 + list_capabilities + get_capability_details + execute_procedure，共七项。
- 新的 list_capabilities 改为结构化摘要响应，是明确的输出契约变更。同步 OutputSchema、协议测试、文档；不得重复在 text 中输出全部 JSON 或正文。
- procedure 白名单仍独立查询 iname，不受摘要分页、has_desp 或详情读取状态影响，名称比较继续使用目录定序。

## 5. 业务调用顺序与提示词

Agent 的流程：

1. 开始业务操作前，读取完整摘要目录。
2. 根据 summary 判断所有适用条目，包括规则类条目及本次需要的业务能力。
3. 适用条目 has_desp=true 时，先读取详情并遵守；false 时，以 summary 为完整说明。
4. 对象名称不明确时定位对象；字段、参数类型或定义需要确认时读取 get_object_details。
5. 执行 procedure 前保留当前用户明确要求、目录授权及 canExecute=true 的确认规则。
6. 按现有查询工具完成任务；分页、截断、引用候选判断及未知执行结果禁止重试的规则不变。

工具说明应明确：有详情的适用条目在使用前读取，不能把 has_desp=true 当作“可读可不读”。不要求每个任务读取全部正文，也不要求已知且无疑义的参数重复查元数据。

规则条目的适用性必须写在 summary 中。例如：

> 所有业务操作均适用，操作前必须读取并遵守详情。

业务范围、身份差异与业务限制继续由数据库配置；不得为了按需加载而搬到固定 MCP 指令。固定指令仅承担通用底线与上述调用关系。

“默认仅围绕目录列明的能力，只有目录允许才扩大探索范围”不按 AD 模式硬编码。需要该限制的角色可以将完整短规则放在 summary、desp 置空。已内置的只读/禁止持久化修改、先读目录及 access_denied 后停止等通用规则不要求在每条摘要中重复。

启用状态与提示词共用条件：未启用目录时，不提及目录、详情或 procedure 工具；启用时说明摘要到详情的顺序。无需向 Agent 解释账号模式、后台表或内部检查机制。

## 6. CB／ECB 条目示例与保留内容

行情摘要示例：

> 查询 CB／ECB 最新可用行情与估值，可按标的股票市场或完整 CB 代码筛选；不支持历史行情。使用前读取详情，确认价格尺度、比例单位、日期及 YTP 口径。

库存摘要示例：

> 查询指定基金、日期的 CB／ECB 及 CB Option 库存与净值占比，可关联最新行情。使用前读取详情，确认默认日期、库存粒度、比例单位及关联规则。

原长说明保留在 desp，尤其保留：空参数行为、默认基金/日期、不回退日期、代码精确匹配、比例单位、NULL 语义、价格尺度、YTP 条件、Option 与 CB 区别、OUTER APPLY 保留缺行情库存、重复匹配检查，以及历史库存关联的是最新行情。

get_object_details 负责可自动发现的结构信息，但不能替代业务口径。本文示例只用于计划及测试设计，不自动新增、授权或修改真实 CB／ECB 记录。

## 7. 已上线数据库核对与其他环境迁移

### 7.1 当前环境

用户已报告表与函数上线，实施从只读核对开始，不默认重跑 CREATE 或 ALTER：

1. 核对 tools_info.summary 为 nvarchar(1000) NOT NULL、desp 为 nvarchar(max) NOT NULL；没有新增 has_desp 实体列或摘要 CHECK 约束。
2. 核对公开函数有六个约定字段，has_desp 是 bit，summary/desp 原样返回，函数没有自动拼接类型/对象标题。核对 id 过滤、角色去重、active 和 ORIGINAL_LOGIN() 绑定。
3. 检查摘要是否补齐；无详情填写 N''。只报告需要管理员处理的 id，不自动补写、删记录或调整权限。
4. 表或函数已满足契约就不修改。若线上仍有旧定义，只交付最小差异脚本由管理员部署。
5. 发布新版 MCP 并重新发现工具：有目录配置为七项，无目录为四项；验证摘要响应不包含 desp。

升级前的旧 MCP 要求非空 desp，不能消费“只有 summary、没有正文”的条目。旧程序与新函数即使字段投影兼容，也不代表语义完全兼容：空 desp 会使旧目录读取失败；移除固定标题后旧文本输出缺少结构化条目标识。不得承诺旧 MCP 可完整使用新契约。

### 7.2 尚未迁移的其他环境

不增加永久新旧模式配置，不自动探测失败后回退全文读取。分阶段操作：

1. 交付检查已有结构的管理员迁移脚本：只对缺失字段新增临时可空 summary；保持现有 desp NOT NULL。不得对已有表重复执行建表脚本。
2. 管理员人工补齐摘要，脚本确认全部记录（包括 inactive）非空白后设置 summary NOT NULL；不增加非空白 CHECK。
3. 如需让旧 MCP 继续工作，过渡阶段必须保留旧函数正文格式及所有有效记录的非空正文；此为临时部署安排，不是最终函数格式。
4. 在受控切换窗口部署最终函数（直接返回原文）与新版 MCP，再启用仅有摘要、desp=N'' 的条目。
5. 新版遇缺列、无效摘要、非 bit 标志等契约错误返回不可用，不回填正文、不绕过目录。

回滚必须恢复已验证的程序与函数组合。使用空 desp 后，先由管理员恢复旧程序需要的正文及函数格式，不能直接切回旧程序，也不能自动复制 summary 伪造旧正文。

不创建数据库、不自动授予权限、不更改真实账号。详情工具使用原公开函数，正常情况下不增加底表或 base 权限。MCP 工具参数 id 对应 SELECT ... FROM 配置的无参数函数() WHERE id=@id，不改变数据库函数签名、不新增详情函数配置。

## 8. 部分失败结果：单独实施的最小修复

本项采用源码评估后的收窄范围，不新增 resultDelivery 字段；保留 success、error、truncated、truncationReason 和 resultSets。

- 读取失败时，保留已加入最终 resultSets 的结果集；正在读取、尚未加入的当前结果集不返回。已因输出上限保留的截断结果集仍保留并标记截断（例如 procedure 后续读取再出错），不得宣称它是完整结果集。
- returnedRows 从最终 resultSets 中累计，不能包含被丢弃的当前结果集行数。
- resultSizeBytes 统一按实际 resultSets 的 UTF-8 JSON 字节数统计；无结果集时约定为 0（不是序列化 [] 的两个字节），有一个正常空结果集时仍计入其列及结构字节。成功、失败、取消和审计使用同一统计口径。
- success=false 且有结果集时，摘要明确“本次查询未完成，已返回部分结果，不能据此判断整次任务完成”；无结果集时保留简短失败反馈。
- 正常完成的空结果仍为成功。正常触发输出截断时保留已有截断语义，不将截断误当 SQL 执行失败。
- 不增加自动重试，不拆分、改写 SQL 批次，不猜测未交付数据或失败语句位置。
- procedure 执行后的异常继续使用 execution_unknown，禁止自动重试；统计修复不暗示事务已提交或已回滚。

该项可独立发布，不需要数据库迁移。resultDelivery 若将来需要，再另行定义零结果集截断等边界，不能直接采用原稿含糊的 partial/none 分类。

## 9. 实施文件与验收

### 9.1 能力目录

实现涉及 CapabilityStore/ICapabilityStore、CapabilityService、CapabilityTools、新详情工具、Program 注册与统一指令生成、表/函数及迁移脚本、配置说明和协议测试。保持现有配置项，无需新增详情函数配置。

必须覆盖：

- 未配置时四项工具且提示词无目录/详情/procedure 引导；配置后七项工具，AD 与 SQL 密码模式均覆盖。
- 摘要包含 skill/grant、有详情/无详情、必须适用规则；无关正文不加载，适用正文在操作前读取。
- list 的 SQL 投影不含 desp；摘要缺失、空白、类型错误不回退全文。
- 函数精确使用 3.2 表达式并返回 bit；N'' 返回无详情。覆盖普通空格、仅换行/Tab、有 Markdown 正文；以数据库计算的 has_desp 为准，不做 Unicode 空白归一化。
- 摘要/详情都不自动增加 ### SKILL／### OBJECT 标题，不剪裁正文，保留原始 Markdown；空白摘要仍被 MCP 拒绝。
- 详情正确返回，有效无详情正常成功；不存在、撤权、inactive、重复 id、异常、取消和超限均有明确测试。
- 多角色去重、任意 ord、同 ord 按 id 排序、分页及响应预算不变。
- 先读详情再撤权，后续详情/执行仍被拒绝；读取详情不会绕过 procedure 独立白名单。摘要后修改正文或清空正文，详情反映本次查询结果，不复用上次状态。
- 已上线环境只读核对，不重复建表；覆盖旧 MCP 遇空正文、移除标题后的语义变化、缺列、非 bit 标志、未补摘要及回滚限制。
- 以 CB 库存关联行情任务对比改造前后完整调用序列的响应总字节数和调用次数；增加一组大量无关条目，证明节省的是无关正文，不遗漏必要规则与口径。额外详情调用属于明确取舍，不宣称调用次数一定减少。

### 9.2 部分失败

实现涉及 SqlQueryService 的结果收集/失败构造/审计以及工具摘要；不改变 QueryResult 字段集合。
