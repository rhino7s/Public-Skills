# CLI 集成规划

状态：规划稿，尚未实现。本文用于确认范围与接口，不代表当前 Release 已支持 CLI。

## 目标

普通用户只需要用白话完成三类操作：

1. 要求 Agent 安装 `sqlserver-readonly-mcp`。
2. 日常由 Agent 通过 MCP 查询和处理资料。
3. 需要固定程序时，要求 Agent 编写 Python 等传统程序；程序通过已注册的 CLI 读取少量数据库资料，不自行保存数据库连接。

用户不需要理解 MCP、CLI、SQL Server 认证或配置路径。安装和写程序的 Agent 负责处理这些技术细节。

## 总体设计

继续使用同一个 `sqlserver-readonly-mcp.exe`：

- 没有 CLI 子命令时，保持现有 MCP `stdio` 行为。
- `query`：执行一次受限只读查询并退出。
- `contract`：输出给 Agent 使用的稳定 JSON 调用契约，不连接数据库。
- `version`：输出程序和 CLI 契约版本，不连接数据库。

第一版不建立常驻服务、不开放 HTTP，也不增加第二套数据库配置。

## 用户与 Agent 流程

### 首次安装

安装 Agent：

1. 从指定 GitHub Release 下载并校验 Windows 包。
2. 将程序解压到 Agent 选择的实际目录；不要求固定下载或安装路径。
3. 在 Release 目录之外建立唯一的 `appsettings.local.json`。
4. 使用实际 EXE 和配置路径建立 Agent 的 MCP 配置。
5. 使用相同路径执行 CLI 注册脚本。
6. 验证 MCP 工具列表及 `sqlserver-readonly-mcp contract`。

CLI 注册仅保存程序路径和配置文件路径，不复制配置内容，也不保存账号或密码。

### 日常 Agent 使用

Agent 继续调用 MCP 工具。用户无需接触命令行。

### 建立传统程序

编程 Agent：

1. 执行 `sqlserver-readonly-mcp contract` 读取当前 CLI 契约。
2. 生成通过标准输入传送 JSON 请求的程序。
3. 不在项目中保存服务器、账号、密码、连接字符串或 MCP 配置路径。
4. 使用固定、小范围、参数化的查询。
5. 将截断、超时、安全拒绝和数据库错误视为失败，不静默使用不完整结果。

## CLI 注册

规划新增用户级 PowerShell 注册脚本，由安装 Agent 调用，并满足：

- 参数为安装 Agent 已确认的 EXE 绝对路径和 MCP 配置绝对路径。
- 将实际 EXE 目录加入当前用户 `PATH`，不要求管理员权限。
- 使用 `SQLSERVER_READONLY_MCP_EXE` 用户环境变量记录本项目登记的实际 EXE，供升级和注销时精确识别旧路径。
- 将现有 `SQLSERVER_MCP_CONFIG` 用户环境变量设置为同一份 MCP 配置路径；环境变量只包含路径。
- MCP 客户端仍可明确传入同一配置路径，避免不同宿主继承环境变量的时间差。
- 更新时移除本项目先前登记的旧 EXE 目录，再登记新目录，避免 PATH 持续累积旧版本。
- 若命令名已被无关程序占用，停止并报告冲突，不覆盖其他程序。
- 重复执行必须是幂等操作；部分失败时恢复原有用户环境变量和 PATH。
- 提供对应的安全注销操作，只移除本项目登记项，不删除程序、配置或其他 PATH 内容。

注册完成后，其他程序只需要知道命令名 `sqlserver-readonly-mcp`。实际安装目录仍可由安装 Agent 自行选择。

## 查询接口

建议调用形式：

```text
sqlserver-readonly-mcp query
```

数据库、SQL 和参数全部通过标准输入传送，不放入命令行参数：

```json
{
  "contractVersion": 1,
  "database": "ExampleDatabase",
  "sql": "SELECT TOP (@limit) [Id], [Name] FROM [dbo].[ExampleTable] ORDER BY [Id]",
  "parameters": {
    "limit": 10
  }
}
```

第一版参数只接受 JSON 的字符串、整数、小数、布尔值和 `null`；参数名称必须符合固定格式。动态值必须使用参数，不得由程序拼接进 SQL。

标准输出只写入一个 JSON 结果对象，并复用现有 `QueryResult` 结构。诊断信息写入标准错误；两者都不得包含账号、密码或连接字符串。

建议退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 查询成功且结果完整 |
| `2` | CLI 请求或本机配置错误 |
| `3` | SQL 被安全规则拒绝 |
| `4` | 数据库连接或执行失败 |
| `5` | 结果达到行数、大小或单元格上限，已截断 |
| `6` | 超时、取消或本机并发繁忙 |

即使失败，标准输出仍返回符合契约的 JSON，供调用程序记录错误类别；程序不得把非零退出码当成正常空结果。

## 第一版安全限制

- CLI 只开放 `query`，不开放 `execute_procedure`、对象定义读取或 Job 搜索。
- 必须复用现有 `SqlSafetyAnalyzer`、`SqlQueryService`、连接工厂、审计日志和配置校验。
- 每次进程只接受一个请求，完成后立即退出。
- 不允许通过 CLI 覆盖服务器、认证、账号、密码、加密选项或查询上限。
- 强制沿用配置中的查询超时、最大行数、结果大小和并发限制，以及程序内部硬上限。
- 结果一旦截断，CLI 返回非零退出码，避免传统程序误用不完整资料。
- 默认不记录 SQL 文本、参数值或查询结果。
- CLI 与 MCP 在审计日志中标明不同调用来源，但使用相同安全判定。

这些限制可以降低误用风险，但不能判断程序属于“简单脚本”还是“量化系统”，也不能阻止用户循环启动 CLI。真正的写入权限、可读取范围和资源治理仍必须由 SQL Server 权限、审计及必要的服务器端资源限制保证。

## 不属于第一版的范围

- 高频轮询、行情串流、批量历史数据同步。
- 长连接、连接池常驻、多请求会话或本机守护服务。
- 并行启动多个 CLI 进程以绕过单次限制。
- 存储过程执行、写入操作、管理操作。
- 取代 Python 数据库驱动、正式数据 API 或量化数据管道。
- 自动替传统程序决定业务查询、字段含义或资料正确性。

## 实施阶段

### 阶段一：共用运行核心

- 将程序启动拆分为 MCP 模式和 CLI 模式。
- 提取两种模式共用的配置、日志、连接、安全分析和查询服务注册。
- 保持现有 MCP 参数与行为向后兼容。

### 阶段二：CLI 契约

- 实现 `query`、`contract` 和 `version`。
- 实现标准输入 JSON、参数绑定、标准输出 JSON 及稳定退出码。
- 明确截断、超时、安全拒绝和 SQL 错误映射。

### 阶段三：安装注册

- 实现用户级注册与注销脚本。
- 检查命令冲突、PATH 更新、同一配置路径、升级替换及失败回滚。
- 更新 Agent 安装说明，使安装 MCP 时同步注册 CLI。

### 阶段四：验证

- CLI 参数解析、契约版本和退出码单元测试。
- 安全拒绝、参数绑定、结果截断及 stdout/stderr 隔离测试。
- 路径含空格时的注册、升级、重复安装和注销测试。
- 验证 MCP 与 CLI 使用同一配置文件。
- 使用本机隔离配置执行一条低成本真实数据库 CLI 集成测试。
- 运行构建、格式检查和公开仓库敏感信息扫描。

### 阶段五：交付

- 先交付源码和测试供人工验证。
- 验证通过后再决定版本号、Commit、Push、Tag 和 Release。
- 未经明确要求，不执行打包或发布。

## 验收标准

- 原有 MCP 功能和安装方式不回归。
- 安装目录任意时，新的终端仍可按固定命令找到 CLI。
- MCP 与 CLI 指向同一份 `appsettings.local.json`，不存在第二份数据库配置。
- 示例 Python 项目不含数据库连接信息或本机绝对路径。
- 持久化写入 SQL、动态 SQL、存储过程及越界查询在连接数据库前被拒绝。
- 完整结果退出码为 `0`；截断和错误均为非零退出码。
- 标准输出始终可由程序稳定解析，日志和标准错误不污染 JSON。
- Release 不包含本机配置、日志、查询内容、认证资料或真实业务信息。
